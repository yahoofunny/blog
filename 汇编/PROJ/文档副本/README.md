# 测试数据（可读副本）

这里的 `.IN` / `.EXP` 是给程序对答案用的原始文件，内容已经原样保留，只是补了换行。

## 为什么要单独放一份

原始文件的换行方式是 **0Dh（CR）单个字符**，这是 DOS 时代的行尾约定（回车但**不换行**，光标回到行首继续覆盖同一行）。对 DOS 程序来说完全正确，因为重定向给程序的输入本来就是一串字符流，`int 21h` 1 号功能只认 0Dh 当"输入结束"，不关心后面跟不跟 0Ah。

但把它当成**文本文件**打开问题就大了：在 VS Code、GitHub 网页、任何 Markdown 渲染器里，单个 CR 会被当成换行或者干脆被忽略，整个文件挤成一行，完全没法读。P1CALC 的输入文件就是典型：

```
12+34␍7*6␍100/7␍3-10␍...
```

所以这里放的是补了 LF 的可读版本，方便人看。**程序实际使用的应该是仓库外那份原始文件**——把可读版本喂给程序，每行末尾多出来的 0Ah 会变成一次额外的输入，程序会多收到一个空行。

## 怎么恢复原始格式

要把可读副本变回 DOS 程序能直接吃的格式：

```bash
# CRLF -> CR，并把多出来的空行压掉（Git Bash / WSL）
perl -pe 's/\r\n|\r/\r/g' P1CALC.IN | perl -0pe 's/\r{2,}/\r/g' > P1CALC.dos
```

或者干脆不折腾原始文件——这些程序都支持交互输入，直接在 DOSBox 里手敲更直观。

## 文件对应关系

| 文件 | 对应程序 | 说明 |
|---|---|---|
| `L02KEY.IN` / `.EXP` | `../LAB/L02KEY.ASM` | 输入 `aB5#`，期望 `A b ? (空) Bye!` |
| `P1CALC.IN` / `.EXP` | `../PROJ/P1CALC.ASM` | 十组算式，含除零和大数 |
| `P2GRADE.IN` / `.EXP` | `../PROJ/P2GRADE.ASM` | 菜单操作序列：录入→显示→排序→统计→退出 |
| `P3CLOCK.IN` / `.EXP` | `../PROJ/P3CLOCK.ASM` | 只有 ESC 和退出，几乎没有可重定向的部分 |

`L12INT` 用的是 BIOS 键盘中断 `int 16h`，绕开了 DOS 输入层，**输入重定向对它无效**，所以没有对应的 `.IN` 文件，目录里那个 `L12INT.MANUAL` 就是标记"这个程序必须真按键盘"。
