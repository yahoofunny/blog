这些图标是什么? —— 全部都是"快捷方式", 不是文件副本
=========================================================
双击任意一个 = 直接打开对应的真实文件夹。
删掉快捷方式不会删掉任何文件。所有实体文件只有一份, 在 ~/asm 里。

五个入口分别是什么:
  导读(先看这里)   学习指南: LEARN.md(总地图) / WHY.md(为什么要学) / 王爽书使用指南
  实例LAB          14 个可编译实例 L01~L14, 每个 .ASM 的注释就是讲义
  试卷EXAM         真题精讲 / 模拟卷 / 答案程序 / 学校真题库(PAPERS) / DEBUG 专项
  项目PROJ         计算器 / 成绩管理 / 电子钟
  工具TOOLS        check.sh(自动批改) 和 quiz.sh(刷题判分)

真实文件都在哪?
  全部在 ~/asm 这一个文件夹里 (桌面图标只是直达各子文件夹的"门")。
  看完整目录: 用 VS Code 打开 ~/asm 文件夹, 或在终端里 cd ~/asm。
  
  顺带说明 "C盘" 的事: DOSBox 是个 DOS 虚拟机, 它把你的 ~/asm 挂载成
  虚拟机内部的 C:\ —— "C盘" 只是那个小窗口里 DOS 的叫法,
  Fedora/Linux 上并没有 C 盘, 实体一直是 ~/asm。
  (你原来的 build.sh / run.sh 和 DOSBox 配置也在 ~/asm 根目录, 位置没动过。)

两个工具怎么用 (在终端里敲):
  bash ~/asm/TOOLS/check.sh L13DIR    # 自动批改: 编译+运行+和标准答案逐字对比
  bash ~/asm/TOOLS/check.sh all       # 20 个题全跑一遍
  bash ~/asm/TOOLS/quiz.sh            # 24 道快问快答, 自动判分+解析

为什么里面有很多"名字很像"的文件?
  (例如 L01HI.ASM / L01HI.OBJ / L01HI.EXE / L01HI.EXP)
  它们不是重复, 是同一个程序的不同形态:
    .ASM   源码, 你要读要改的东西
    .OBJ   编译中间产物(编译时自动生成, 可以不管它)
    .EXE   可执行程序(在 DOSBox 里能直接跑)
    .EXP   标准答案(自动批改时拿来对比的期望输出)
    .IN    测试输入(自动批改时喂给程序当"键盘输入")
  试卷库 EXAM/PAPERS 里的 "原始/" 和 "txt/" 也是同理:
    原始/ = 从学校仓库下载的 doc/pdf 原件 (排版完整)
    txt/  = 从原件提取的纯文本 (终端里翻得快)
