## 1. Basic concepts

### 1.1 Definition of search

** Search**: the process of finding data elements in the data set that meet certain conditions.

### 1.2 Basic terms

| Terminology
|------|------|
| **Figure of data elements of the same type
| ** Key** The only data item in the data element that identifies this element
| ** Looking for success** | Found data elements that meet the conditions in the search table
| ** Failed to find** data elements that meet the conditions do not exist in the search table
| ** Average length of search (ASL)** Core indicator to measure efficiency of search algorithms

### 1.3 Average length of search ASL

** ASL (Average Search Length)**: average number of keyword comparisons during search.

**ASL Success**:
$$ASL_{成功} = \sum_{i=1}^{n} P_i \cdot C_i$$

- $P_i$: Find No. $i$ Probability of an element
- $C_i$: Found No. $i$ Number of comparisons required for individual elements

**ASL failed**:
$$ASL_{失败} = \sum_{j=1}^{m} P_j \cdot C_j$$

- $P_j$Other Organiser $j$ Probability between sectors
- $C_j$: Number of comparisons required to determine failure in the zone

### 1.4 Classification of the search tables

- ** Static Search Table**: search and search only (sequence, double search)
- ** Dynamic search table**: Query + Insert + Delete (two fork sort tree, Hash table)

## 2. Order of search

### 2.1 Basic thinking

From the end of the table, the key word by word is compared until the target is found or a complete table is passed.

### 2.2 Algorithmic realization

```c
// 带哨兵的顺序查找
int SeqSearch(int a[], int n, int key) {
    a[0] = key;           // 设置哨兵
    int i = n;
    while (a[i] != key)   // 从后往前找
        i--;
    return i;             // i=0 表示查找失败
}
```

**Sentry role**: every loop judgement omitted `i >= 1` Border conditions and efficiency gains.

### 2.3 Performance analysis

| Indicator Value
|------|-----|
| ASL Success (Equal Probability) $\frac{n+1}{2}$ |
| ASL failed $n+1$(no sentry)/ $n$(Sentry guard)
| Time complexity $O(n)$ |
| Space complexity $O(1)$ |

### 2.4 Applicable scenes

- Linear tables (both sequential or chain storage)
- Table element disorder
- Small data volume

### 2.5 Order of the chart search

If the sequence is orderly, the search does not need to go through the end:
- **ASL Failed** = $\frac{n}{2} + \frac{n}{n+1}$ ≈ $\frac{n}{2}$

## 3. Two-point search

> ** Also known as**: half search

### 3.1 Preconditions

- ** For an orderly sequence only**
- ** Not applicable to chain tables** (link tables cannot access intermediate elements at random)

### 3.2 Basic thinking

The target value is compared to the middle element at half a time between the search areas:
- Equal poignant search success
- Target &lt; Median ~ Continue searching in the left half.
- Target > Median

### 3.3 Algorithms achieved

```c
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = low + (high - low) / 2;  // 防止溢出
        if (a[mid] == key)
            return mid;                 // 查找成功
        else if (a[mid] > key)
            high = mid - 1;             // 左半区
        else
            low = mid + 1;              // 右半区
    }
    return -1;                          // 查找失败
}
```

### 3.4 Determination of trees

The binary search process can be described as a **balanced fork tree**, known as ** decision tree**.

** Nature of the tree**:
- It's a balanced fork tree.
- Yes. $n$ A node to determine tree height $\lceil \log_2(n+1) \rceil$
- Number of comparisons when finding success = depth of the corresponding node in the determination tree
- Number of comparisons when finding failure = parent node depth corresponding to an empty pointer

### 3.5 Performance analysis

| Indicator Value
|------|-----|
| ASL Success $\frac{n+1}{n}\log_2(n+1) - 1 \approx \log_2(n+1) - 1$ |
| Time complexity $O(\log n)$ |
| Space complexity $O(1)$ |

### 3.6 Example of ASL calculation

** Example: Order table `[7, 14, 18, 21, 23, 29, 31, 35, 38]`, two points to find successful ASL.

Construct a determination tree (number in nodes is a subscript, not a value):

```
              4(23)
           /       \
        1(14)      6(31)
       /    \      /    \
     0(7)  2(18) 5(29) 7(35)
       \     \           \
       1*    2*          8(38)
                          \
                          8*
```

- Finds 1 success: 1 node $1 \times 1 = 1$
- Find 2 success: 2 nodes $2 \times 2 = 4$
- Find 3 success: 4 nodes $3 \times 4 = 12$
- Find 4 success: 2 nodes $4 \times 2 = 8$

$$ASL_{成功} = \frac{1+4+12+8}{9} = \frac{25}{9} \approx 2.78$$

## 5. Trident sorting tree BST

> ** Also known as **: fork finding tree, fork searching tree

### 5.1 Definitions

**Fork sort tree** is empty or meets the following characteristics:
1. If the left tree is not empty, the value of all nodes on the left tree** is less than the value of the ** node
2. If the right sub-tree is not empty, the value of all nodes on the right sub-tree** is greater than the value of the ** node
3. The left and right trees are each a fork sort.

> ** Focus of the examination**: Medium Sequence BST has an incremental sequence

### 5.2 Finding Operations

```c
BSTNode* BSTSearch(BSTNode* root, int key) {
    if (root == NULL || root->key == key)
        return root;
    if (key < root->key)
        return BSTSearch(root->left, key);
    else
        return BSTSearch(root->right, key);
}
```

** Search process**: from root to root if it is successful; less than root if left; more than root if right.

### 5.3 Insert Operations

Insert a new node** Must be a leaf node**.

```c
BSTNode* BSTInsert(BSTNode* root, int key) {
    if (root == NULL) {
        BSTNode* node = (BSTNode*)malloc(sizeof(BSTNode));
        node->key = key;
        node->left = node->right = NULL;
        return node;
    }
    if (key < root->key)
        root->left = BSTInsert(root->left, key);
    else if (key > root->key)
        root->right = BSTInsert(root->right, key);
    return root;  // key 已存在则不插入
}
```

### 5.4 Delete Operations

Situation Analysis (set to delete node as `p`）：

| Situation | Operation |
|------|------|
| `p` It's a leaf node.
| `p` Only left tree/ right tree
| `p` Replaced by ** or ** / ** / ** / / / / / / / / / / / / / / / / / / / / / / / / / / / / / / / /

> ** Centred forward**: bottom right of the left tree  
> ** In the middle order follow**: bottom left node in the right subtree

### 5.5 ASL Analysis

- ** Best case** (balanced):$ASL = O(\log n)$
- ** Worst case** (unilateral slash):$ASL = O(n)$

The insertion order affects the shape of the BST, which leads to balancing the need for a fork tree.

## Red and black trees

### 7.1 Definitions

**Red and black tree** is a binary sorted tree that meets the following characteristics:
1. Each node is** red** or** black**
2. ** Roots** Black
3. ** Leaf Node (NIL)** Black
4. ** Can't have two consecutive red nodes**
5. Path from either node to each of its leaves,** the same number of black nodes** (the same black height)

### 7.2 Red and Black Tree vs AVL Tree

| AVL tree, twilight tree, twilight tree.
|----------|--------|--------|
| Balancing conditions | Tight (high difference 1) Easier (black height equal) |

### 7.3 Nature extrapolation
