## 1. Basic knowledge

### 1.1 Machine language

- ** Machine language**: The collection of binary machine commands, CPU can be executed directly, but people can hardly read and write directly.
- The compilation language is based on the machine language and is supported by symbols.

### 1.2 Generation of compilation languages

- Machine language is hard to remember, difficult to check, so use ** amulet** (e.g. `mov`、`add`This is the motivation for compiling the language.

### 1.3 Composition of compilation languages

The compilation language consists of three types of instructions:

1. ** Compiled directive**: the machine code identifier, which is the core of the compilation language and has the corresponding machine code;
2. ** Hypocrisy directive**: no corresponding machine code, performed by a compiler `segment`、`end`）；
3. ** Other symbol**: if `+`、`-`、`*`、`/`, identified by compiler, without corresponding machine code.

### 1.4 Storage

- ** Storer**: Parts of CPU that read/written data when running, consisting of several ** storage units**.
- Role of memory: Storage of ** Directives and data required for CPU implementation**.

### 1.5 Instructions and data

- ** The instructions and data memory/disk do not differ, and are binary information**; the CPU treats the information at work as a directive and some as data, and the difference is only in ** application**.

### 1.6 Storage units

- Storage units are divided into several storage units, each numbered from 0 to ** address**.
- 8086 A storage unit = **1 bytes (byte) = 8 bit**; 1 word (Word) = 2 bytes.

### 1.7 CPU for memory reading and writing

To read and write data, CPU must interact 3 types of information with an external chip:

1. ** Address information**: address of the storage unit (through address bus);
2. ** Control information**: read or write (through control bus);
3. ** Data message**: content read/written (transmitted via data bus).

### 1.8 Address bus

- ** Address bus width** determines ** address ability of CPU**: N root address line → addressable $2^N$ A storage unit.
- 8086 **20 address bus** $2^{20}$ = **1 MB** memory space.

### 1.9 Data bus

- ** Data bus width** determines how much data is transmitted at one time** (bit numbers).
- 8086 Data bus **16 ** 2 byte; 8088 only 8 by 1 byte.

### 1.10 Control bus

- ** Control bus** is a collection of ** some different control lines** and each single line expresses a control message.
- Direction cannot be generalized: some are sent by CPU (e.g. "read" signals) or others by external chips to CPU (e.g. interrupt the request line).

> ** Calculating Example**: address bus width is 20, memory address space size = $2^{20}\ \text{B} = 1048576\ \text{B} = 1\ \text{MB}$。

### 1.11 Memory address space (overview)

- In each PC, the size of the memory address space is limited by the width of the address bus; the CPU locates it uniformly.

### 1.12 Main Board

- The main plate contains cores connected through the bus: CPU, storage (RAM), peripheral chips (interface cards), extended slots.

### 1.13 Interface cards

- CPU cannot directly control external settings (showers, keyboards, soundboxes), but is indirectly controlled by issuing orders to ** repositories (ports)** on interface cards.
- CPU sends a command to the interface card via the bus, which controls the external work as ordered.

### 1.14 Storage chips of all types

| Classifications Characteristics Example
|------|------|------|
| Random memory RAM | readable, blackout lost | primary, visible |
| Read-only memory ROM | read only, power is cut | BIOS ROM (with an opener) |

### 1.15 Memory address space

- ** Memory address space**: CPU views various types of storage as a ** Logical repository consisting of several storage units**, with each physical repository having an address space in the address space.
- 8086 PC address space allocation (from low to high): main repository address space → visible address space → various ROM address space. ** The reading and writing of an address is actually the reading and writing of the physical memory to which it belongs. **

- **16 bit structure**: Operator handles up to 16 bit data at a time, register has a maximum width of 16 bits, and route between repository and operator is 16 bit.

### 2.6 Method of giving physical address by 8086 CPU

$$\textbf{物理地址} = \textbf{段地址} \times 16 + \textbf{偏移地址}$$

- x16 In binary, i.e. ** left 4 bit** (hexadecimal 1 bit left, followed by 0).
- Example: Sector address 123CH, offset address 0008H → Physical address = 123C0H + 0008H = **123C8H**.

### 2.7 The essence of "part address x 16+ offset address = physical address"

- The CPU gives the physical address of the memory unit by "basic address (part address x 16) + offset address relative to base address".
- Two 16-bit addresses (part, offset) synthesized a 20-bit physical address.

### 2.8 Concept of paragraph <span class="wm-star" aria-hidden="true"></span>

- ** "Paragraph" is not really divided into memory**, but rather a logical concept resulting from the CPU sub-location approach; a number of "paragraphs" can be arranged as needed.
- The starting address of a segment (paragraph address x 16) must be **16 multiple**.
- Offset address 16 bits a maximum of **64 KB**$2^{16}$）。
- The same physical address can be obtained by a combination of "part addresses: offset addresses" such as 21F60H = 2000H: 1F60H = 21F6H:000H.

### 2.9 Segment Depositary

- 4 Sector senders: **CS, DS, SS, ES**.
- 8086 Positioning instructions or data should be used at all times using the "Step Address: Offset Address"; a sector address is stored in a sector register.

### 2.10 CS and IP <span class="wm-star" aria-hidden="true"></span><span class="wm-star" aria-hidden="true"></span><span class="wm-star" aria-hidden="true"></span>

- ** CS (Code Segment Depositary) + IP (Directive Pointer Depositary)**: Instructions CPU to currently read command addresses.
- ** At any moment, the CPU uses the CS:IP pointers as instructions**:
  1. Read commands from CS x 16+IP and send them into command buffers;
  2. **IP = IP + length of command read** (to the next command);
  3. Execute the directive, step 1.
- 8086 After power is activated or restored: **CS = H, IP = 000000H**, i.e. starting from 0H unit - which is the first command of the BIOS ROM.

### 2.11 Directives to modify CS, IP

- 8086 Most repositories can be modified with mov, but **mov cannot be used to set up CS, IP**.
- The commands that can modify CS and IP are collectively referred to as** transfer instructions**, the simplest being `jmp`：

```asm
jmp 2AE3:3        ; 同时修改：CS=2AE3H, IP=0003H（段间转移）
jmp ax            ; 仅修改 IP = ax（段内转移，功能上类比 mov ip, ax）
```

### 2.12 Code segment

- Treats a memory as a code segment, simply placing its segment address on CS, and the deviation of the first command on IP, and CPU executes the instructions accordingly.
- ** The code segments are artificial; CPU only recognizes CS:IP.**

## 5. [BX] and Loop Directives

### 5.1 [BX]

- `[bx]` is the memory unit with the offset address in **bx** and the default DS address.

```asm
mov bx, 0
mov ax, [bx]      ; 等价于 mov ax, (DS:0)
inc bx            ; bx = bx + 1
```

- `inc 寄存器`Add 1;`dec 寄存器`: minus 1 (the two instructions are often followed by moving points).

### 5.2 Loop Directive <span class="wm-star" aria-hidden="true"></span><span class="wm-star" aria-hidden="true"></span><span class="wm-star" aria-hidden="true"></span>

- CPU Implementation `loop 标号`：
  1. **(cx) = (cx) − 1**；
  2. cx: ** Not 0, transferred to mark**; 0, down.
- ** Number of storage cycles** in cx.

** Classic example: calculation $2^{12}$(no multiplier)**

```asm
    mov ax, 2
    mov cx, 11         ; 循环 11 次，每次翻倍
s:  add ax, ax         ; ax = ax × 2
    loop s             ; cx-- ≠0 就跳到 s
```

Implementation result: AX = $2^{12}$ = 4096 = **1000H**。
