## 1. 不是汇编啰嗦，是 CPU 只会这么点事

第一次写汇编的人都会被这些规矩气到：

```asm
ADD VAR1, VAR2      ; ✗ 不行，必须过寄存器
SUB AL, VAR1        ; ✗ 不行，AL 是 8 位，VAR1 是 16 位
JNZ VAR1            ; ✗ 不行，跳转目标必须是标号
DIV BX              ; ✗ 前面忘了 XOR DX, DX 就崩溃
```

这些不是汇编语言故意刁难人，**每一条背后都是一条硬件事实**：

| 你觉得莫名其妙的规矩 | 硬件里真实的原因 |
|---|---|
| `ADD VAR1, VAR2` 不合法，必须经寄存器中转 | ALU 的加法电路一端**必须接寄存器**，没有"内存 + 内存"这根线 |
| `SUB AL, VAR1` 报类型不匹配 | AL 是 8 位，VAR1 是 16 位，电路上两根不同宽度的线接不上 |
| `JNZ VAR1` 不合法 | 跳转是把地址塞进 IP，而 VAR1 里装的是**数据**，不是地址 |
| `DIV` 前必须 `XOR DX, DX` | 除法电路固定按 `DX:AX ÷ 操作数` 接线，DX 有垃圾就等于给了个天文数字 |
| 大小写转换要 `AND 11011111B` | 字母的 ASCII 码第 5 位就是"大小写开关"，电路只会按位操作 |
| 参数用 DX 传、结果放 AX | 不是规定，是和 DOS 系统调用这个"插座"约定好的接口 |

一句话：**汇编不负责让你写得爽，它负责如实转述机器的规矩。**

你嫌它啰嗦，其实是在嫌机器只会这么点事。高级语言让你**看不见**这些规矩——不代表它们不存在。

## 2. 你写 C 的一行，本来就有这么多步

这是这门课最值钱的一个认知。

写一行 C：

```c
a = a + b;
```

让编译器吐汇编出来看（`gcc -S -O0 -masm=intel x.c`）：

```asm
mov eax, DWORD PTR b
mov edx, DWORD PTR a
add eax, edx
mov DWORD PTR a, eax
```

**mov → add → mov**，和你们课本上 8086 的标准套路一模一样。区别只是跑在 64 位 CPU 上、语法换了个皮。

同样的，真题里那个：

```asm
MOV CX, 5
LP: ...
    LOOP LP
```

就是 C 里 `for (i = 0; i < 10; i++)` 生成的 `cmp + jle` 循环的亲戚。

所以：

> **汇编不是"另一门语言"，它是所有语言的地基。**
> 你写 C 的时候，这几步一直在执行，编译器只是当了你的代笔。

学汇编，等于给 C 语言装上 X 光机。

## 3. 以为的啰嗦，其实已经是最高级的偷懒

`INT 21H` 一句就能在屏幕上显示一串字符。这不是因为汇编厉害，是因为 **DOS 帮你写好了几百行硬件驱动**。

CPU 本身连"把字符画到屏幕"都不会——它只会往一块特定的内存（`B800H`）里写字节。这就是 `L10MEM` 那节"显存直写"讲的原理：屏幕上的每个字符，本质上就是内存里的两个字节。

```
你调 int 21h        →  DOS 帮你算坐标、填属性、滚屏
你直接写 B800:0     →  这些活儿全得自己干
```

**你每享受一层抽象，就少写一堆汇编。** 这门课教的，就是这层抽象最底下的样子。

## 4. 学它到底图啥

说句实话：日常工作写业务代码，用不着汇编。这门课的价值不在"以后用它写程序"，而在于下面这些事**绕不开它**：

**调试和性能**。程序为什么崩？为什么慢？栈溢出长什么样？排查到最后都是看汇编。寄存器、栈、标志位，就是这套"底层视力"的起点。

**嵌入式和单片机**。身边一切带电的东西——洗衣机、汽车、键盘——里面的小芯片，编程要么是汇编，要么是"你看得懂汇编才调得动"的 C。

**操作系统和驱动**。中断、栈切换、任务调度，全是汇编概念。现在学的段寄存器、SP、中断向量表，在操作系统课里会一个不少地回来找你。

**安全和逆向**。病毒分析、漏洞利用、软件保护，全在汇编层打仗。招聘网站上"逆向工程师"的入门要求就一句话：熟读 x86 汇编。

**这门课的知识会到处复用**。计算机组成原理、操作系统、接口技术，后面几门课都默认你学过它。而且它训练的是"程序每一毫秒在机器里是什么状态"的思维方式——这个思维比语法本身值钱。

## 5. 一张考点地图

把 20 多份历年试卷翻完，考点其实就那么些。而且**每个考点都对应上面说的某条硬件真相**：

| 考点 | 考的是哪个硬件事实 | 在哪练 |
|---|---|---|
| 寻址方式辨认（立即/直接/间接/相对/基址变址） | CPU 找数只有这几种接线方式 | `L04BX` |
| 指令合法性与找错 | 上面那张表里的接线限制 | `L05CMP` |
| 标志位 CF / ZF / SF / OF | 跳转靠标志位传递情报，运算电路顺手产生 | `L08NUM` |
| 数据定义 DB/DW/DD、DUP、ORG、`$` | 数据在内存里怎么摆，决定程序能不能跑 | `L13DIR` |
| 栈与 SP 变化（push/pop/call/ret） | 栈是程序流程的物理基础 | `L07FUNC` |
| 除法/乘法/CBW/CWD | 乘除电路的位宽跟寄存器不是一一对应 | `L07FUNC` |
| 伪指令 SEGMENT/PROC/ENDP/END | 汇编器组装程序的图纸标记 | `L01HI` |
| 宏 MACRO / `&` / `%` | 汇编唯一"省事"的手段：文本替换 | `L14MAC` |
| DEBUG 上机（U/T/P/R/D/G） | 唯一能当场看见寄存器怎么动的题 | `DEBUG练习.md` |
| 中断 int 21h / 10h / 16h | 系统调用就是和 DOS/BIOS 的接口约定 | `L11TIME` `L12INT` |
| 程序设计（字符串/数值） | 前面一切的综合 | `Z22B1~3` |

看出规律了吗：**考试每一类题，都是在问"机器里的某个东西，你知道它长什么样吗"**。

所以复习的正确姿势不是背，是**每类考点都亲手跑一遍**。

按出现频率排一下，性价比最高的是这几个：

| 考点 | 出现份数（共 22 份） |
|---|---|
| ORG / `$` / 段内偏移计算 | 17 |
| DEBUG 上机题 | 16 |
| SEGMENT 段定义 / 段寄存器 | 15 |
| DUP / 数据定义 | 14 |
| 宏 MACRO（`&` 拼接 / `%` 展开） | 13 |
| SHL/SAR 移位与标志位 | 13 |
| 寻址方式辨认 | 13 |

前四个加起来覆盖了大半张卷子。

## 6. 四条学习建议

**每次写代码问"三连"**：这句执行完，AX 是多少？标志位变了吗？栈里现在有什么？

能答上这三问，考试所有"读程序写结果"的题全拿。

**遇到任何"为什么"就做实验**。不确定 `db $` 存什么？写五行跑一下看列表文件。这套材料里每个 `.ASM` 都能随手改随手跑，这就是你的实验室。`L13DIR` 那节课就是靠这个办法，发现教材答案和汇编器实际口径差了个数。

**错题只订正一遍不够**。把错题涉及的实例重跑一次，改几个数看规律变不变。改一次胜过读十遍。

**DEBUG 就是游戏机**。上机题的快乐在于你能"暂停时间"看 CPU 内部。花半小时玩 `debug`，比读一章书都值。
