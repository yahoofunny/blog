## 一块圆屏，和它周围的一圈硬件

先看规格。这块板子的核心不是屏幕，而是它把常用外设几乎都塞进了一张名片大小的 PCB：

| 项目 | 规格 |
|---|---|
| 主控 | ESP32-S3R8，双核 LX7，240MHz |
| 内存 | 512KB SRAM + **8MB OPI PSRAM** |
| 闪存 | **16MB** NOR |
| 屏幕 | 1.85 英寸圆形 IPS，360×360，**ST77916**，QSPI，RGB565 |
| 触摸 | **CST816S**，I²C `0x15` |
| 六轴 | **QMI8658**，I²C `0x6B` |
| 音频 | ES8311 编解码器 + ES7210 回声消除，双麦克风、扬声器焊盘 |
| 其他 | PCF85063 RTC、BQ27220 电量计、microSD（4 位 SDMMC） |
| 无线 | 2.4GHz Wi-Fi b/g/n + BLE 5 |
| 供电 | USB-C 或 MX1.25 接口的 3.7V 锂电池，板载充电 |

这块板子最反直觉的一点，是**只剩 3 个空闲 GPIO**（7、8、18），其余引脚已经被屏幕、触摸、音频、SD 卡和闪存/PSRAM 总线占满。想加东西，基本只能走引出的 I²C。知道这件事之后，很多“再加一个按键/传感器”的想法会自然消失，设计也会更克制。

## 两个固件，共用一只宠物

设备原厂就是双固件布局：`factory` 里是主应用，`ota_0` 里是一套完整的小智语音系统，不是空的 OTA 槽。这个项目没有推翻它，而是把 Arduino 启动器放进 `factory`，把改过界面的小智语音宠物放进 `ota_0`，沿用设备已有的分区表：

```text
factory   0x020000  6.88MB   Arduino 启动器 + 小游戏 + 相册
ota_0     0x6C0000  4.00MB   ESP-IDF 小智语音宠物
assets    0xAC0000  4.00MB   共享资源
```

启动器里点开 CLAWD PET，如果检测到语音固件，就写 `otadata` 并重启切到 `ota_0`；语音固件里长按 BOOT，再把 `factory` 设回启动分区。整个过程在设备上完成，不需要电脑，也不需要断电。

这套布局的代价是：**不能用通用的整片烧录流程**。`idf.py flash` 自动生成的参数指向 `factory`，还会顺带写引导程序和分区表；一旦覆盖 `ota_0`，语音助手就没了，切换逻辑会陷入循环。项目里的 `deploy_game.sh` 只写 `factory` 应用，`install_voice_pet.py` 只写 `ota_0`，两个工具都刻意绕开了“一把梭”的烧录方式。

## 启动器没有用 LVGL

大部分 ESP32 圆屏项目会直接上 LVGL。这个项目的启动器反而不：它把一帧 RGB565 直接画进 PSRAM 里的帧缓冲，再切成 DMA 条带送给 ST77916。每个应用实现同一个 `Game` 接口，文字、精灵、圆环和图标都用项目自己的绘制原语。

这样做的好处是**完全掌控每一帧**：主页圆环的缓动、图标的呼吸环、游戏的场地和粒子的顺序，都在一个确定的绘制流程里；坏处是轮子得自己造，圆环描边、文字渲染和精灵旋转都要写。项目里甚至有一个把纯色图转成 2bpp 索引 C 头文件的脚本，还有一个把 24 个 GIF 原样嵌进 flash 的构建脚本——因为在这个内存尺度上，一张 RGBA 图片就是奢侈品。

独立的小智语音固件则使用它自己的 LVGL 图片适配器。两套渲染路径并存，互不打扰；也正因为它们不是一个东西，性能数据不能互相套用。

## 养一只住得进圆屏的宠物

CLAWD PET 不是“一个会动的图标”。它有一套完整的小状态机：

- **同一只宠物**：蛋、七种成长形态、喂食、抚摸、拖动、休息和清洁；对话时保留形态与配饰，显示表情和中文字幕。
- **20 种像素配饰**：花朵、安全帽、耳机、巫师帽等叠加在原身体上，体型和比例保持一致；衣柜支持预览、取消和保存。
- **轻量但完整**：饥饿、能量、心情、清洁、健康五项需求，加上成长值和图鉴收集；旧存档会迁移，不会因为加字段就从头养。

配饰是“画”上去的，不是换一张更大的图。这样做省内存，也让每一件配饰都能和任何形态组合，而不是给每种形态各画一套。

## 性能：从 16.6 fps 到 27 fps

主页最早在实机上只有 **16.6 fps**。奇怪的是，绘制本身只占约 14.4ms，真正的大头是送屏：整屏 360 行、每条 DMA 传 8 行、共 45 批，一批传完才能复用缓冲，合计约 45ms。

优化分两步：

1. **少算一点**：主页的椭圆轨道坐标只初始化一次，每帧图标位置在排序和绘制之间复用；圆环描边只扫描两侧窄边，像素判定不变。绘制从约 14.42ms 降到 12.65ms。
2. **少传几次**：把内部 DMA 缓冲从 8 行加到 32 行，整屏从 45 批降到 12 批；后来又推到总线允许的 40 行，降到 9 批。送屏从约 45ms 降到约 23ms。

在同一块设备、同一套测试固件、相同转动轨迹下，主页从 **16.55 fps** 升到 **27.03 fps**，GAMES 文件夹从 **16.68 fps** 升到 **27.74 fps**。正常主循环另测约 8 秒，主页约 26.94 fps，GAMES 约 27.54 fps。

这里有个容易吹过头的地方：主机上绘制耗时节省了约 45%，但设备整体 FPS 的提升主要来自送屏批次减少。只改绘制时，主页只有约 16.95 fps。**不要把主机 CPU 的收益直接写成实机收益。**

后来又加了一条：主页静止时只有选中图标外那圈呼吸环在动，于是按时间把整屏刷新限到约 **15 Hz**；拖拽、倾斜转动和缓动未收敛时仍全速出帧。实测静止时的送屏量降到原来的约 **1/2.4**。

相册则是另一个瓶颈。SD 卡里一千两百万像素的照片，每切一张都要重新解码，耗时 **427~625ms**，滑动就是半秒白屏。现在用 PSRAM 里的三帧缓存（上一张/当前/下一张，各 259KB）把切图变成 `memcpy`：实测切到下一张只要 **12ms**。这里面修了两个真 bug：

- 换图时只旋转槽位标号、不搬 777KB 像素，结果三个槽位开始描述别人的像素，缓存会交出**错误的那张图**。现在指针和标号一起旋转，并用“缓存命中也报和解码相同的校验和”验证 28 张全部一致。
- 预解码把图拷回帧缓冲时，如果用户刚好滑走，会盖掉新图。现在加了代数守卫：期间发生过切换就放弃恢复，重画当前图。

预解码本身仍占用主循环 440~640ms，属于“用户正在看当前图”的空闲期；跟手滑动过渡还没做。

## 电池：百分比会骗人

BQ27220 的默认满电容量是 3000mAh，但这台设备实际装的是 **500mAh / 1.85Wh** 的电池。项目用串口命令 `C500` 备份原参数后，只改电量计 RAM 里的满电容量和设计容量，读回校验并重新估算；配置成功会写进 NVS，启动器发现电量计回到默认值时恢复。整个过程不烧 OTP，不改充电芯片、电流校准或电池保护参数。

更麻烦的是充电状态。仅插线、或界面显示 100%，都不能证明正在充电；充电宝和普通充电器也不会发送 USB 主机数据包。所以 SETTINGS → POWER 分开显示 USB CONNECTED、CHARGING、DISCHARGING、FULL 和实际电流。重插电脑 USB 后，电量计曾持续报告 0mA；固件现在只在“电脑连接、读数有效、零电流、SLEEP 标志持续 2 秒”时尝试一次最多 4 秒的降负载恢复，屏幕可能短暂熄灭，随后回到原页面。实机恢复后读数为约 **+155mA**，状态显示 CHARGING。

## 踩过的坑，比功能更值得记

- **空闲 GPIO 只有 3 个**。7、8、18，其余全被板载外设和总线占用；扩展优先走 I²C。
- **两套 LVGL 版本**。Arduino 示例附 LVGL 8.4.0，ESP-IDF 和原厂系统用 9.5.0，`lv_scr_act()` 和 `lv_screen_active()` 不兼容。复用示例前先确认版本。
- **恢复原厂备份时不要让 esptool 改写镜像头**。原厂引导程序头标记为 DIO，运行时才升到 QIO；强行指定 `--flash_mode qio` 会让设备反复看门狗重启。恢复时用 `--flash_mode keep --flash_size keep --flash_freq keep`。
- **USB 原生 CDC**。这块板没有 USB 转 UART 桥接芯片，启用 `CDCOnBoot=cdc` 才能在 USB 上看到 `Serial`；串口监视器要启用 DTR、保持 RTS 无效。
- **Git Bash 调 ESP-IDF**。`cmd.exe /c` 会被 MSYS 改写路径，要写 `cmd.exe //c`；`MSYSTEM` 变量会让 `install.bat` 报错，项目脚本会先清掉它。

## 自己做一块

项目采用 **AGPL-3.0**，Clawd 美术素材来自另一个 AGPL-3.0 项目，第三方材料和条款都在 `NOTICE.md` 里。仓库不包含上游 SDK、闪存备份和编译产物，需要按 README 自己准备 Arduino / ESP-IDF 环境。

**动手前先完整备份 16MB 闪存。** 这块板子的原厂系统、分区表和语音固件，比一块空白开发板值得保护得多。启动器用：

```bash
PARTITION_SCHEME=custom ./tools/build.sh compile system
./tools/deploy_game.sh system COM3
```

语音宠物用 PowerShell 的 ESP-IDF 流程；详细步骤、分区说明和验证命令都在 [仓库 README](https://github.com/yahoofunny/esp32-badge) 里。
